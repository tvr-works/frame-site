## Deliberate boundaries

- Landscape virtual displays only, 1440 × 900 point work areas. The physical browser geometry scales the native logical coordinates. macOS menu bar/dock reservation, app minimum sizes and multi-display arrangement are not measured from the owner's machine.
- Six simulated windows per workspace, four columns, ten persistent workspaces. Resize stops before a column weight falls below 180 or a row weight below 150. These readability guards are demo limits, not native Frame minimum-size claims.
- The owner requested fixed workspace banks in this demo: 1–5 belong to the left display and 6–0 to the right. Initial visible workspaces are 1 and 6. Selecting a workspace shows it on its assigned display and activates its most recently focused window, or the empty workspace itself. This assignment is a demo configuration choice, rather than the native default affinity policy in the evidence table.
- Transfers follow the moved window at the owner's request: show the destination workspace on its assigned display and activate the exact moved window, including when other destination windows were more recently focused. This is equivalent to native send followed by workspace activation; the native default send alone stays on the source workspace. Transfer-to-self and failed/invalid/full-destination operations preserve focus and visibility.
- Single-display mode makes every workspace available on that display. Restoring dual displays restores the fixed banks, retains the active workspace and focused window on its assigned display, and shows workspace 1 or 6 on the other display. Window state is preserved. This is not the full native nearest-point/previous-workspace hotplug algorithm.
- Create and close model demo app lifecycle actions. No native CLI command is implied. Background registration, app-specific exclusions, minimized/hidden/fullscreen windows, mouse drag, native app constraints and configuration overrides are outside scope.
- Focus outline, display headers and intentionally simplified translucent skeleton interiors are explanatory demo chrome, not a claim that Frame draws those controls over macOS. Window interiors were simplified at the owner's request during review.
- Native focus/command outcomes are verified against fixtures/traces for the supported subset; this is not a full port of every native command, platform hook or failure code.

## Scripted playback

The pure session reducer owns playing/paused state separately from layout. Every story command still uses the immutable native-derived model. Initial autoplay is permitted only after first on-screen observation and when reduced motion/background state allow it. Replay explicitly starts from blank. Pause preserves the exact current layout and shortcut cue. Background/offscreen transitions and opening a modal pause and require explicit Play to continue. Reduced motion suppresses visual transitions and initial autoplay, with explicit playback still available.

The scene holds empty for 1.2 seconds, then opens browser, notes and editor windows at 1.2-second intervals on workspace 1. After a 2.25-second settle, Option K/J/H/L focuses up, down, left and right without changing geometry. Adding Shift moves the editor right into a new column, left back into its stack, then up and down within that column. The editor stays in the bottom row for the resize chapter: Option Shift Control H/H/H expands the rightmost column left, then L shrinks it from the left. K/K expands the bottom row upward; J shrinks it from the top. Both width and height changes retain the same focused editor and are asserted against before/after model geometry. Option Shift 7 sends the editor to the right display; Option Shift 1 returns it to the left with focus following both ways.

Each shortcut caption is a short structural result, shown in a larger label centered between the monitor feet. The label, full modifier/direction chord and command update in the same reducer beat, then hold together until the next action. Repeated actions retain the same wording. The label is not an autoplay live region; the existing polite region reports pauses. The phrasing map is in [demo-script.md](demo-script.md).

The returned scene holds for 2.4 seconds before closing starts. Windows then close individually at 1.6-second intervals using the model’s close transition and MRU focus. Each red dot retains its 650 ms cue before its window closes; the action label stays on the previous result until the close command, then changes with it; the cue holds its ID through Pause and clears on close, Replay or the next cycle. Shortcut keys stay quiet during closing. Geometry transitions take 550 ms, giving setup and teardown time to settle. After the last close, a 1.8-second empty hold resets the session; the opening adds another 1.2 seconds before the first window. The approximately 43-second cycle restores fresh IDs and weights. Pause, visibility/background suspension and dialogs also stop closing and the empty hold.

The monitor title bars, traffic lights, workspace banks, modifier rows and direction keys are read-only presentation. Only Play/Pause and Replay operate the demo. There are no global or scoped keyboard listeners, application-role keyboard region, click-to-focus windows, close controls, display setup switch or workspace buttons. Normal browser keyboard navigation remains available. The earlier hands-on demo and held-key input were removed at the owner’s request because native global shortcuts can conflict with the browser experience.

The monitor artwork and shortcut illustration are hidden from assistive technology; a persistent screen-reader description explains the full sequence. A polite atomic status reports pause (including the current cue and scene) without narrating every autoplay beat or loop. The centered visible action label is readable normally without announcing every loop. Automated WCAG checks supplement browser checks; a full VoiceOver user study is not claimed.

## Accessibility tooling exception

Base UI 1.9.0 intentionally exposes visually hidden focus guards as unnamed buttons to Safari/VoiceOver so swiping redirects focus into a modal. This produces WebKit axe `button-name` findings on the library’s sentinels. The [maintainer explicitly recommends excluding only `[data-base-ui-focus-guard]`](https://github.com/mui/base-ui/issues/5237). The installed `utils/FocusGuard.mjs` and `FloatingFocusManager.mjs` were inspected before applying that narrow scan exclusion. No app controls, rules or lint checks are excluded, and no guard markup is modified. Dedicated Chromium/WebKit tests check forward/backward modal focus containment and Escape restoration. Real VoiceOver swipe behavior remains untested locally.
