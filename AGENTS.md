# Frame site

This is a separate repository from the native app at ../frame. Keep native source, releases, installed apps and shared taps read-only unless a later user instruction explicitly commissions that work. This initial milestone is local-only: do not create a hosted repository, push, deploy or modify hosting/DNS.

Read README.md, docs/simulator.md and docs/ci-deployment.md before changing behavior. The approved composition is recorded in design-qa.md; the owner selected the matte-monitor modifier-ladder mockup, with one headline, workspace keys locked 1–5 left / 6–0 right and quiet, translucent skeleton window interiors. Keep help progressively disclosed and the demo dominant.

Use src/demo/model.ts for all commands. Autoplay and manual controls share those transitions. Preserve native layout fixture/trace parity and hierarchical column/window MRU. The owner-requested demo policies lock workspace banks and follow transferred windows by activating their destination; document these differences from native defaults. Preserve the distinction between directional focus and movement. Do not invent native commands. Keyboard capture is scoped to the focused demo, supports the displayed Option chords plus plain-key controls, and releases with Escape or normal Tab navigation. Ignore editable targets, composition and Command shortcuts. Never send real Option hotkeys through automation on the owner’s desktop; verify modifier handling with synthetic browser DOM events.

Run npm run check, npm run build and npm run test:browser. For delivery changes, also run SITE_DEPLOYMENT_MODE=production npm run build and npm run test:artifact, then restore a preview build. Keep dependencies pinned and update the Playwright package/image/peer together. Do not suppress lint to get a pass. The narrow upstream-documented axe focus-guard exception is recorded in docs/simulator.md and covered by separate focus-containment tests.
